## 3. Ambient "Attic" Soundscape Design

The Pack Rat attic soundscape should feel **warm, slightly dusty, and safe** with occasional reminders of the old house:

### Background Layer (always playing, low volume)
- **Wind outside**: Use `old attic wind.wav` or `wind building attic.aif` — processed through a low-pass filter to sound distant
- **House settling**: Occasional random wood creak from the Creaking Wood collection (use random timer, 15–60s intervals)
- **Dust motes ambience**: Subtle high-frequency room tone (can be generated with filtered white noise + reverb in Godot's Audio Bus)

### Interactive / Situational Layers
- **Wind gust**: When game is idle for a while, trigger a soft wind gust sound
- **Rain on roof**: If time-of-day system exists, rainy weather could activate a rain-on-roof ambience layer
- **Rat scurrying**: Soft padding sounds when the rat moves between nest sections (layer the mouse-scuttling sounds)
- **Item pickup sparkle**: Use the Item Pickup Chime (lyre) or 8-Bit Collect for collected items
- **Crafting/placing**: Use Breaking Sticks, Crunching Twigs, or Wood Ants textures for nest-building actions

### Atmosphere Tips
- Apply a low-pass filter (~200Hz) on the master ambient bus to simulate the muffled acoustics of an enclosed attic space
- Add subtle reverb (Room Size: 0.3–0.5, Wet: 20–30%) to all ambient layers to simulate the wooden attic echo
- Use Godot's `AudioEffectReverb` on an "Ambience" bus

## 4. UI Sound Effect Best Practices for Idle/Incremental Games

Based on research from GameJuice, Unwinnable, and game design theory:

### Core UI Audio Palette
- **Hover**: 50–100ms soft tick, very low volume — confirms element is interactive
- **Press**: Clear click/confirm tone on pointer-down — communicates "action registered"
- **Error**: Muted downward-pitched tone or buzz — distinctly different from success
- **Menu open/close**: Directional sounds matching visual slide direction (left-to-right pitch sweep)

### Upgrade / Prestige Sounds (The "Dopamine Ding")
- **Key insight**: Slot machine psychology applies directly — short bright rising-pitch sounds make players *feel* like they're winning
- The most satisfying upgrade sounds share: bright timbre, rising pitch (major 3rd or 5th interval), fast attack, <500ms decay
- **The FREE Satisfying Upgrade SFX pack** (Hazard Pay) was specifically designed for incremental games and provides 5 upgrade styles with 2 variations each

### Level-Up & Milestone Hierarchy
- **Small upgrade**: Single short chime (major 3rd rise)
- **Medium milestone**: Two-note ascending phrase (e.g., C→E)
- **Big milestone (×10, ×100)**: Three-note ascending arpeggio (C→E→G)
- **Prestige / major achievement**: Full musical phrase (4–8 notes) with slight reverb tail — should feel celebratory but harmonize with BGM key

### Progression Audio Arc
1. **Button press** → confirm click
2. **Item acquired** → short pickup pop
3. **Upgrade purchased** → chime
4. **Milestone reached** → extended rising tone that resolves
5. **Prestige** → full fanfare with musical phrase + screen flash

### Golden Rules
- Design UI sounds in the same key as the background music to avoid dissonance
- Never reuse the success/confirm sound for failure states
- Keep UI sounds under 500ms (except prestige/achievement)
- Always respect the SFX volume bus — never hardcode `volume_db`
- The **FREE Satisfying Upgrade SFX** pack has 10 ready-to-use sounds covering exactly this hierarchy

## 5. Godot Audio Integration Tips

### Architecture: AudioManager Singleton (Autoload)

Godot's recommended pattern per the official docs and community consensus:

```
res://audio_manager.gd  (set as Autoload in Project Settings)
```

### Audio Bus Setup

Create these buses in the Audio tab (saved to `default_bus_layout.tres`):
1. **Master** (default) — final output
2. **BGM** — routes to Master
3. **SFX** — routes to Master
4. **Ambience** — routes to Master (for attic background layers)
5. **UI** — routes to Master (for interface sounds)

### AudioStreamPlayer Decision Matrix

| Node Type | Use For |
|-----------|---------|
| `AudioStreamPlayer` | BGM (place in scene or on AudioManager), UI sounds, non-positional SFX |
| `AudioStreamPlayer2D` | Positional sounds in the game world (items dropping, rat scuttling near camera) |
| `AudioStreamPlayer3D` | Not needed for 2D pixel-art game |

### Patterns: Dynamic Instantiation vs Pooling

**Start with dynamic instantiation** for SFX:
```gdscript
func play_sfx(stream: AudioStream):
    var player = AudioStreamPlayer.new()
    player.stream = stream
    player.bus = "SFX"
    add_child(player)
    player.play()
    player.finished.connect(func(): player.queue_free())
```

**Switch to object pooling** only if profiling shows a bottleneck:
```gdscript
# Pre-create pool of 32 players, round-robin usage
const POOL_SIZE = 32
var pool: Array[AudioStreamPlayer]
var pool_index = 0

func _ready():
    for i in range(POOL_SIZE):
        var player := AudioStreamPlayer.new()
        player.bus = "SFX"
        add_child(player)
        pool.append(player)

func play_sfx(stream: AudioStream, volume_db := 0.0):
    var player = pool[pool_index]
    pool_index = (pool_index + 1) % POOL_SIZE
    if player.playing:
        player.stop()
    player.stream = stream
    player.volume_db = volume_db
    player.play()
```

### Volume Control
```gdscript
# Convert 0.0–1.0 slider to dB
AudioServer.set_bus_volume_db(
    AudioServer.get_bus_index("SFX"),
    linear_to_db(clampf(linear_volume, 0.0, 1.0))
)
```

### Performance Tips
- Set `max_polyphony` on BGM player to 1 (never layer music)
- Use `.ogg` files for BGM (smaller, streaming-friendly)
- Attic ambience: apply `AudioEffectReverb` on the Ambience bus (Room Size: 0.4, Wet: 25%)
- Low-pass filter (~200Hz) on Ambience bus helps sell the "inside an attic" feel
- Dust motes: generate as filtered white noise on Ambience bus, not as a separate audio file

### Architecture Debate: Singleton vs Service Pattern

Two mainstream approaches in Godot:

| Approach | Pros | Cons |
|----------|------|------|
| **Autoload Singleton** (`AudioManager`) | Simple, globally accessible, well-documented, survives scene transitions | Tight coupling, harder to refactor, all code depends on it |
| **Service Layer** (`Services.audio.play_sfx()`) | Loose coupling, easier testing, each service isolated | More boilerplate, extra indirection |

**Recommendation for Pack Rat**: Start with an `AudioManager` autoload singleton. The game scope is small enough that the coupling concerns won't bite. Refactor to service layer if the project grows significantly.
